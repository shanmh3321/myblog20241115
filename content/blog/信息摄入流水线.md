## 收藏夹的真正问题：把「学习态」的内容无法被「消费」

短视频、推文是**消费态**内容：不用准备，随时拿起，随时放下。

高质量播客、长访谈、技术分享是**学习态**内容：要腾出一整块时间，要专注，要「坚持」。

收藏夹吃灰久了，久而久之就是垃圾桶，后来我想通一件事：别让自己坚持，去改变内容的形态。让长内容先以短内容的样子出现，有了兴趣、且它值得，我再往下走一层。

## 三层台阶

现在任何一条内容在我这儿有三层，每一层都是一个完整的消费单位，也都能往下走：

| 层 | 形态 | 花多久 |
|---|---|---|
| 一层 | 日报里的一句亮点 | 两分钟 |
| 二层 | 一篇博客式的阅读版 | 十分钟 |
| 三层 | 原音 / 原视频，只看那一段 | 一小时（或五分钟） |

三层之间是通的：日报里每条都带文档链接和原片链接；文档末尾附完整逐字稿，可以全文检索；拿不准的地方直接在内嵌的豆包里追问。最后是回到浏览器看原片，借助chatGPT浏览器插件——它能读到当前页面的视频内容，把它当私人视频导游，直接把我带到感兴趣的那一段。

这个跟我的运动系统就比较接近了，服装鞋子都可随时进入运动状态，每天可以只做一个俯卧撑，但当自己有状态时，也可以完成一小时的运动量。它不需要我"坚持"。

## 我先做了主动的信息筛选

入口是飞书机器人，因为它是我本来每天都会打开的APP。工具如果需要多一个动作（切窗口、开网页、点收藏），它就会死在第三天。

技术上刚好也合适：飞书自建应用支持**长连接**接收事件，不需要公网 IP、不需要内网穿透——这一点让「拿自己的笔记本当服务器」从玩笑变成了可选项。

链路是：我发一条链接给机器人 → 按 URL 类型路由 → 长任务进本地队列，不阻塞飞书回调 → 每一步回一条进度（两分钟不说话，我会以为它挂了）→ 转成文字 → 生成阅读版 → 建飞书文档、归档知识库 → 回我链接。

**内容怎么拿到：**

- **小宇宙**：没有公开 API，但单集页的HTML信息中就有音频直链。
- **转写**：阿里云百炼的 Paraformer，走「录音文件识别」的 URL 模式——把公网直链直接交给它，音频根本不用下载。2.5 小时、143MB 的一集，约 **1.5 分钟**出 4.6 万字。
- **YouTube**：supadata 的字幕接口，每月约 100 个视频的免费额度，秒级返回纯文本。

**关键的一步不是「转文字」，是把逐字稿改写成能读的文章。** 4.6 万字的稿子我一样读不完，所以文档前面是 LLM 生成的阅读版，末尾才附完整逐字稿备查。改写按 1.2 万字切块逐段处理，再补总览；提示词里几条是硬要求：「永远不要高度浓缩」「关键数字和原话如实保留」「不许新增事实」。单块失败只标注缺失，不整篇失败——全自动系统里，「部分完成」比「全有或全无」好用得多。

部署没上云，就跑在我自己的 Windows 上：一个启动脚本加桌面快捷方式。代价是：**电脑必须常开**，偶尔手滑关掉，就在手机上用UU远程应用连回去点一下。

## 再交给AI来筛选和推送信息

在解决「我发链接它才动」后，又出现了新问题「我不知道今天该看什么」。

**信源**：小宇宙的「我的订阅 → 导出 OPML」就是所有播客的 RSS；YouTube 用频道 RSS，频道 ID 问 GPT 要就行；另外接了 Zara Zhang 那个开源的 `follow-builders`，把「X 上的短观点 + 播客长内容」一起抓下来。

**什么时候跑**：每天定时跑；启动时补检查一次，防止前一天关机漏掉；也可以在飞书里发「日报」立刻跑一轮。

一集播客取文本，按成本从低到高依次尝试：**发布方自带 transcript → 有 YouTube 版就用 supadata → 兜底才用 ASR**。日常大多数内容根本用不到 ASR。

**日报的设计取舍：** 一天只发一条，内部按「长内容 / 短观点」分区块。长内容每条只给**一个**亮点加一个链接；X 推文不建文档，逐条忠实翻译就好。推荐语用「一个真实的朋友」的口吻：挑一个独特角度、一个反常识点，不平铺概要。

## 回头看

让这套东西能持续用下来的不是功能或产品精致，反而是简单粗糙、方便与低成本：不依赖云资源，自己电脑就够用；交互入口放在我本来就在用的地方；ASR、获取字幕接口、GPT插件等都是现成工具。

我跟我朋友说过一句话：成本会影响动机。降低这条路上各种成本、不谈坚持，只看兴趣。回到这件事上，先别管是否读完，先让它变成读得完的样子。
